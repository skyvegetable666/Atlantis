# 首个真实任务：修复 CSV 账单统计程序

状态：本地 Issue 草稿及候选任务包。具体任务与评分规则尚未作为正式实验条件确认。

## 要实现的行为

提供一个单居民可完成、允许多居民自行分工的 Python 修复任务。居民获得相同的需求、初始代码和公开测试，提交修复后的完整项目；研究者使用独立用例评分。

现有数字统计任务验证了工作闭环，但不足以观察模块修复与成果整合。候选任务覆盖 CSV 读取、带日期筛选的金额汇总、JSON 报告与命令行连接。

不在任务说明或居民提示词中指定岗位、领导或合作方式。消息、子任务和付款是行为记录，不直接增加质量分。

## 模块与接口

任务包目录：`benchmarks/csv_ledger_v1/`。

| 模块 | 输入 | 输出与错误 |
| --- | --- | --- |
| 读取 | CSV 文本 | 固定字段的记录列表；无效数据抛出 ValueError |
| 汇总 | 记录列表、可选起止日期 | 以整数分表示的汇总；区间无效抛出 ValueError |
| 报告 | 汇总 | 固定结构的 JSON 文本；金额为两位小数字符串 |
| 命令行 | 输入文件与可选起止日期 | 成功写 stdout；输入错误写 stderr 并退出 2 |

完整接口与边界条件见任务包的 `task.md`。任务包不依赖 City、数据库、供应商或实验台 UI。

公开投影仅包含 task.md、初始项目和公开测试。独立用例、参考修复和开发者验证工具由研究者保存，不进入居民工作区或 Observation。

## 评分建议

读取、汇总、报告、整体运行各占 25 分，每类 8 个独立用例。总分按通过用例比例计算，保留部分分；32 个用例全部通过才记为通过。

建议主任务通过后才验收付款；这项结算策略仍待正式实验配置确认，不在本 Issue 中改动现有城市规则。居民间委托继续由发布者按事前条款验收，独立评分另外记录。

评分不调用模型，不导入参考答案生成期望值，预期结果使用固定数据定义。正式实验前冻结任务版本、评分版本和内容哈希。

2026-10-20 开发验证：初始代码 34.375 分，参考修复 100 分；分别重新引入读取、汇总、报告、命令行缺陷时，得分为 71.875、75、90.625、87.5。公开测试为 5 项，独立评分为 32 项。以上验证材料与评分器，不代表真实居民已完成此任务。
