# 原型实现记录

日期：2026-10-20。

## 已落实

- Python 3.11+ 标准库、SQLite、进程内契约和本地观察页面。
- 控制器获取观察、调用运行时、提交行动；运行时不依赖城市内核。
- 任务、通信、账户、成果规则分模块；城市应用流程协调原子变化。
- 同一个模型接口支持脚本 fixture 与已有网关的真实模型。
- 运行记录、消息、成果、账本、调用、评分可持久检查与导出。
- 本地 Git 初始化及 GitHub Issue / PR / CI 模板。
- 独立的 CSV 账单代码修复候选任务包，包含固定接口、公开材料、独立评分与参考修复；尚未接入居民工作工具。

## 为启动而采用的临时配置

以下只用于验证原型，不代表研究设计已全部确认。

| 项目 | 当前选择 |
| --- | --- |
| 第一种任务 | 公开数字列表的 JSON 统计 |
| 独立评价 | 与原始输入计算出的四项统计逐项对照 |
| 居民数量 | 1 或 2；初始居民资金总量相同 |
| 居民目标 | 根据规则完成有报酬的工作，增加自己的净 credit |
| 初始资金 | 居民共 100，资金池 100；主任务托管报酬 60 |
| 内部调用计价 | 每次模型或工具尝试 1 credit，单独记入资源费用账户 |
| 调度 | 按持久 turn 在可调度居民中轮转；每次决策一个动作 |
| 等待 | 状态变为 waiting；可见消息或公开任务变化可唤醒 |
| 真实费用 | 保存供应商用量；货币费用缺少可核实来源时保持待确认 |

首个任务非常简单，适合检查模块接合，不足以检验复杂合作优势。脚本演示包含指定的委托路径，真实居民只使用统一目标和动作说明。

## 本次验证

- `python3 -m unittest discover -s tests -v`：31 项通过，包含事务回滚、并发超支、重复结算、隐私、暂停、重启、网关流式解析和 HTTP 后台运行。
- 单居民真实运行 `0e794e16322f`：3 次模型调用，成果独立评分通过并结算。
- 双居民真实运行 `37bb6b1a3df5`：5 次模型调用，成果独立评分通过并结算；没有成功投递的消息或子任务。后续检查发现 Lin 有两次发送尝试因参数错误被拒绝，不能将没有成功消息解释为没有沟通意图；未完成实际委托或雇佣。
- 真实运行使用 `.env` 指定模型；未指定居民领导者或分工。模型与工具调用在实验调用名额限制内执行。
- 调试中失败的运行继续保留在数据库中，未重写为成功。真实供应商货币费用仍待核实。
- 浏览器检查任务与成果、资金与调用页面，未发现控制台错误；1280 与 390 像素宽度均无页面横向溢出。
